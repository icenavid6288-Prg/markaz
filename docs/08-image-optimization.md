# بهینه‌سازی تصاویر سایت (WebP + فشرده‌سازی)

> دستور فنی برای تیم توسعه — هدف: کاهش حداقل ۳۰٪ از حجم کلی صفحات.

## قانون کلی

- **فرمت استاندارد همه تصاویر جدید: WebP.** (به‌جز آیکون‌های SVG که همین‌حالا برداری‌اند.)
- PNG/JPG موجود فقط در دو حالت مجاز است: تصاویر نیازمند شفافیت پیچیده (لوگو/نشان) یا فایل‌های مرجع داخلی که هنوز تبدیل نشده‌اند.

## گام‌ها

1. **تبدیل دسته‌جمعی به WebP**
   - CLI با `cwebp` (بسته libwebp):
     ```bash
     for f in public/images/*.png public/images/*.jpg; do
       cwebp -q 80 -m 6 "$f" -o "${f%.*}.webp"
     done
     ```
   - یا در Node (پایپ‌لاین بیلد فعلی) با `sharp`:
     ```js
     import sharp from 'sharp';
     await sharp('input.png').webp({ quality: 80 }).toFile('output.webp');
     ```

2. **فشرده‌سازی تک‌تک تصاویر شاخص** با TinyPNG / TinyJPG / Squoosh (کیفیت ۷۵–۸۵؛ برای بنر و عکس‌های بزرگ ۶۵–۷۵ کافی است).

3. **به‌روزرسانی مسیرها در ادمین/دیتابیس** — مقدارهای ذخیره‌شده (Hero، درباره ما، کاور مقاله‌ها، عکس مدرس/کوچ/اعضای تیم) به `*.webp` تغییر کند. فرم‌های آپلود از قبل `png,jpg,jpeg,webp` را می‌پذیرند.

4. **اندازه‌های پاسخگو (Srcset)** — برای تصاویر شاخص حداقل دو سایز (`640w` و `1280w`) تولید و با `srcset` استفاده شود تا موبایل نسخه کوچک‌تر را بارگیری کند.

5. **تأیید کاهش حجم** — قبل/بعد هر صفحه با DevTools (Network → Disable cache) مقایسه و در گزارش ثبت شود؛ هدف: حجم صفحه ≤ ۳۰٪ قبلی.

## پرهیزها

- تصاویر استوک در بنر/صفحه درباره ما ممنوع است؛ تصاویر واقعی از دکتر بیدی، محیط مرکز و لحظات دوره‌ها (عکاسی داخلی) جایگزین شود.
- `loading="lazy"` برای تصاویر پایین صفحه و `loading="eager"` فقط برای تصویر Hero حفظ شود.
