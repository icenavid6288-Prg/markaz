# تست رگرسیون ظاهری (Visual Regression)

این سوت با [Playwright](https://playwright.dev) از صفحه اصلی، خدمات، فهرست دوره‌ها،
جزئیات دوره، فروشگاه و بلاگ در هر دو تم روشن و تیره، در نمای دسکتاپ، تبلت ۷۶۸px و
موبایل اسکرین‌شات می‌گیرد و با تصویر مرجع (Baseline) مقایسه می‌کند. نمای تبلت برای گرفتن شکستگی‌های میانی بین breakpointهای
موبایل و دسکتاپ اضافه شده است. اگر تغییری در استایل یا چیدمان چیزی را بشکند، تست Fail می‌شود و
تفاوت در `test-results/` ذخیره می‌شود.

## پیش‌نیاز

- کروم Playwright نصب باشد (یک‌بار):
  ```bash
  npx playwright install chromium
  ```
- دیتابیس پیش‌نمایش (`.freebuff/preview.sqlite`) موجود باشد — همان‌طور که در
  `.freebuff/run.md` توضیح داده شده ساخته می‌شود. سوت به‌صورت خودکار یک سرور جدا
  روی پورت `8010` با همین دیتابیس بالا می‌آورد، پس سرور پیش‌نمایش می‌تواند هم‌زمان
  روی `8000` روشن بماند.

## اجرا

```bash
npm run visual:test     # مقایسه با تصاویر مرجع
npm run visual:update   # بازسازی تصاویر مرجع (بعد از تغییر عمدی طراحی)
```

## پیکربندی

- پورت سرور تست: `VISUAL_PORT` (پیش‌فرض ۸۰۱۰)
- مسیر دیتابیس: `VISUAL_DB` (پیش‌فرض مسیر دیتابیس پیش‌نمایش همین پروژه)
- آستانه تفاوت: `maxDiffRatio: 0.0005` (۰٫۰۵٪) در `tests/visual/lib/snapshot.js`
- انیمیشن‌ها در هنگام اسکرین‌شات غیرفعال می‌شوند و بخش‌های Scroll-Reveal اجباری
  نمایان می‌شوند تا تصاویر پایدار باشند.
- مقایسه با یک ماتچر سفارشی (`lib/snapshot.js`) انجام می‌شود نه `toHaveScreenshot`
  پلی‌رایت؛ چون حلقه پایداری داخلی آن روی این صفحات بلند RTL هرگز به نتیجه نمی‌رسد
  حتی وقتی صفحه بین دو عکس پیکسل‌به‌پیکسل یکسان است. در صورت Fail، تصویر تفاوت در
  `test-results/visual/` ذخیره می‌شود.
- `--update-snapshots` همه‌ی بیلاین‌ها را بازنویسی می‌کند؛ اجرای معمولی فقط
  بیلاین‌های جاافتاده را می‌سازد و بقیه را مقایسه می‌کند.

## افزودن صفحه جدید

در `home-services.spec.js` یک مورد به آرایه `PAGES` اضافه کنید، سپس
`npm run visual:update` را برای ساخت Baseline اول اجرا کنید. برای جزئیات دوره، slug
یک دوره منتشرشده و پایدار را استفاده کنید. Baselineها با پسوند
`desktop`، `tablet` و `mobile` از هم جدا می‌شوند.

## تستهای تابعی تنظیمات (admin-settings.spec.js)

علاوه بر اسکرینشاتها، `admin-settings.spec.js` چند تست تابعی هم دارد:

- لنگرهای قدیمی صفحه تکصفحهای تنظیمات (`#sms`، `#payment`، `#winback`) را به
  صفحات جدید (`/admin/settings/sms`، `/admin/settings/payments`،
  `/admin/settings/automations`) ریدایرکت میکند؛ لنگرهای درونصفحهای مثل `#brand`
  در همان صفحه میمانند.
- هر چهار صفحه جدید تنظیمات (`/admin/settings`، `/admin/settings/sms`،
  `/admin/settings/payments`، `/admin/settings/automations`) رندر میشوند.

ورود از طریق شماره ادمین seeder (`09330961312`) و رمز عبور انجام میشود؛ مقدار رمز از
`ADMIN_PASSWORD` خوانده میشود و در صورت نبودن آن `password` است. ورود فقط یکبار برای
کل فایل انجام میشود. این تستها فقط روی پروژه دسکتاپ اجرا میشوند؛ موبایل و تبلت Skip
میشوند.
